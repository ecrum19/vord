Vocabulary of Restrictive Datasets (VoRD)

VoRD provides machine-readable terms for SPARQL endpoint maintainers to advertise live query restrictions in an endpoint's service description.

Who Should Use VoRD? (and where to start)

VoRD supports different audiences. Use the pathways below to find role-specific guidance and artifacts.

Endpoint Maintainers

Publish service restrictions so clients can detect endpoint behavior and limits before query submission.

  • Start with the usage specification and required restriction patterns.
  • Use the basic and exhaustive examples as templates for real endpoints.
  • Validate output with SHACL before publishing.

Query Engine Developers

Integrate VoRD parsing and validation into clients, middleware, and query orchestration components.

  • Use described data to guide query planning and execution.

Users (Consumers of Endpoints)

Inspect published restrictions to choose query shapes and request pacing that are less likely to fail.

  • Use term pages to interpret each published restriction quickly.
  • Use the Wikidata example as a concrete, real-world pattern.
  • Check status code and retry hints to implement safer retry behavior.
